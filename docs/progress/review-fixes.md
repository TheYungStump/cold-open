## Decisions

1. Each finding is its own commit: spec, test and fix together. The branch is pushed after each group.
2. **F4.** `Dispatcher::discard` keeps a copy of the journal (`<journal>.discarded-<ms>`) whenever the session holds unsaved work, and `doc.close` reports the copy in a `journal_discarded` warning. As a result the app's "Don't save", and Discard on a never-saved script, now leave a copy too, and the dialog says so.
3. **F4.** An agent may not set aside a writer's unsaved work by any route: `doc.close {discard: true}`, `doc.revert` and `doc.open {recover: "discard"}` all fail with `not_your_step` when the work at stake includes a writer's entries. Each of these keeps a copy, but the writer would never be shown that copy.
4. **F1.** `coldopen run` keeps recovered work in the journal when the batch did not touch it. If the batch edited on top of recovered work, it keeps a copy and names it. A batch's own edits, which can be made again by rerunning it, are still deleted with no copy (`Dispatcher::discard_rerunnable`).
5. **F5.** `doc.new` refuses any non-empty journal at its path with `already_exists`, without analysing it. `doc.open` is the way to recover it or set it aside. `doc.new` also runs all its checks before it closes the open document, so a refusal leaves that document open.
6. **F2.** Save-as judges the target's journal exactly as opening the target would. Where the open would recover, the save fails with `unsaved_changes` (the existing code, with `details.path` naming the target) and writes nothing.
7. **F14.** With no entries, a file that matches the header's (or a marker's) fingerprint, or holds the header's document, is nothing to recover; anything else recovers the header's document with `commands: 0` and `external_change: true`. The fingerprint is checked first, so a file not in Cold Open's normal form is not mistaken for a change. The app's recovery dialog has its own sentence for this case.

8. **A2.** `doc.revert` keeps a copy whenever the document has unsaved changes, not only when the journal has entries. The app's start-up scan judges a recent script's journal as opening it would (`coldopen_core::dispatcher::journal_holds_work`). It still counts lines in `Unsaved/`, where a journal without entries is a script nobody typed in.
9. **F10.** The fault injection is a `#[cfg(test)]` hook in `Journal` (a short write, a failed flush, a failed truncate), the only way to make a write fail on all three OSes. A failed flush also cuts the entry back, because the session rolls that edit back. A journal that can't be cut back is "broken" until a header is written; `save_prepare` skips its marker then, or the app could never save its way out.
10. **F3 / C4.** Saves are serialized in core rather than queued per front end: a prepared save holds the session's save token (a per-session save number), and any other save fails with a retryable `save_in_progress`. The app's Mod+S already waits (`save_again`). An agent's `doc_save` gets the error and retries, rather than having its answer held back until a background save finishes; that keeps the link's one-request-one-answer flow simple, and a background save takes milliseconds. The palette's raw form goes through the same refusal until F7 routes it through the app.
11. **A6.2.** Each session has a process-unique id. A commit for a closed, reopened or reverted session changes nothing and reports `save_superseded`, which the app shows as information ("... has finished; the file holds the version saved then"), not as "not saved". Whether the reopened script then saves over that newer file is F11's question.
12. **F11.** One flag, `overwrite`, serves both F11 (replace a file another program changed) and F13 (replace a file that is not the open document): both mean "replace what is there". It is writer-only (`writer_only` for agents, enforced in core by author, so it holds over the link and in `coldopen mcp`). The check reads the whole file before a save in place, on the UI thread for the background save; for a script that is a fraction of a millisecond. The window between that check and the rename is milliseconds and is accepted. In the app's question, Enter chooses Save as, which keeps both versions; the dialog was rendered headless and checked (2026-10-16).
13. **F13.** An existing target that is not the open document needs `overwrite`, checked before the F2 lock and journal checks. Agents can never pass it (A8's point), so an agent exports or saves to a new path. The app passes it only when the system dialog asked about that very path (not when the app added the extension). The CLI's `export` subcommand passes it, like `convert`, since a person named the output; `run` and `serve` batches send raw commands and must pass it themselves. The F2 tests now pass `overwrite`, as the app does, so they still test the lock and journal checks behind it.
14. **F19.** Refused in core by author, not only in the link's denylist, so it also holds in `coldopen mcp`'s own dispatcher, where a recovered journal may hold the writer's Shot. The user asked for "over the link"; the core rule covers that and the local case with one check, and an agent can still save after changing the element itself.
15. **F17.3.** The old-phase journals were made by building 0654f37, f26f59c and ce171cb in a scratch worktree and running each build's `serve --stdio` on our own short scene, with the request files kept beside them. The test compares the recovered document's block JSON with the same build's `doc.get`, not exported text, since the writer's normal form changed between phases.
16. **F8.** Replay compares the ids a result names (`id`, and each `results[].id` of a batch) and `undone`/`redone`; nothing else. The rule is in `journal.md`, together with its consequence: a change in what a command does needs a new `semantics` number (F16), since results alone won't show it.
17. **F9.** On a divergence, the trusted prefix is replayed again on a fresh session rather than cloning the document before every entry: divergence is rare (and rarer after F8), while a clone per entry would slow every recovery.
18. **C1 / F16.1.** Each history step remembers the seq of the entry that made it. An undo or redo entry names that seq, or, for a step from before the journal's last restart, carries the step's operations, command, label and author. This keeps the journal truncated at each save (it stays small) instead of keeping a whole session's journal, or writing the whole undo history into every header. A save also ends the typing group, so a burst never merges across a restart. Replay still re-checks a recorded `merge` against the grouping rules, since a group keeps only its first inverse; if that ever disagrees, the step reference catches the difference at the next undo instead of reversing the wrong step.
19. **F16.3.** The header records `semantics` (1 today), the host name (the `gethostname` crate, Apache-2.0, already in the tree through x11rb; justified in the PR) and the script's canonical path (for a script with no file yet, the canonical folder plus the name). A journal is foreign when either recorded value differs; older journals without them are treated as local. "Offer, never auto-apply" is a refusal with a new error, `journal_foreign`, plus `recover: "apply"`, so every front end gets the choice, not just the app. A foreign journal with nothing to recover is restarted silently. Renaming the computer or moving a script's folder makes its journal foreign, which costs one question, never work.
20. **Grok's notes.** The flusher's two handles: the assumption is documented in `journal.md`, as asked. Header size: a header holds one copy of the document, written at each save. For a 120-page script that is about the size of the script's JSON, and it is written as part of a save that already writes the script. No change now; the phase 5 plan should keep revision data out of the header, or reference it.
21. **F7.** The params form routes `doc.open`, `doc.new`, `doc.close`, `doc.revert` and `doc.save` through the app's flows (`leave`, `save`/`save_as`, `reload`), so the form can never skip a question the menus ask. `doc.new` with a `path` is refused there: the app's new scripts start untitled. Links are bound to the path they attached to: any change of the open script's path closes them, Save as of an untitled script included, and a request that still arrives for the old script closes its link.
22. **F12.** `doc.revert` numbers the file's blocks from the session's `next_id`, so ids stay monotonic for the life of the open document and old ids fail. Agents stay attached across a revert (the writer's own Revert or recovery Discard): with no reuse, their old ids are safely invalid, and they read the document again. Two existing tests that typed into `b_2` after a revert were updated to the new ids; they relied on the reuse. Reopening a file (`doc.open`) still numbers from `b_1`: that is a new document, and links do not survive it (F7). F18 discusses ids that survive a reload.
23. **F20 / C8.** One request per link: the reader waits on an "answered" signal from the app's `LinkWriter::send` before reading the next line, and ends when the app drops the writer (closing the link). That bounds the app's inbox to one request per link, four in all. The outbound queue is a bounded channel (an answer, a coalesced `changed` wake-up, a close); `changed` revs are kept in an atomic, and only one wake-up waits. At most 8 connections may be in their handshake. A thread blocked writing to a client that never reads stays blocked until that client goes away; memory stays bounded, and that client is same-user and holds the token.
24. **P2.** On Windows, an empty non-blocking pipe read returns `Ok(0)`, the same as end of stream, so during the handshake `Ok(0)` means "nothing yet" there and the loop waits for the deadline. A client that really left fails the next read. Unix reports `WouldBlock`, as before.
25. **F6.** UTF-16 is kept on save (like the BOM and CRLF), so no question is needed. A Windows-1252 file cannot be kept without a Windows-1252 writer (and new characters may not fit), so its first save reports a `reencoded` loss through the existing lossy-save path, and the writer decides. Detection without a byte-order mark looks at the first two bytes only, as the .fdx reader does.
26. **F15.** The timing test compares growth (4× the input must take under 9× the time), not a fixed budget, so it holds in CI's debug builds and on slow runners; a quadratic step shows as about 16×. The emphasis procedure keeps CommonMark's rules exactly, and only its data structures changed: a linked list for the delimiter stack, and a prefix-sum pass for styles. The conformance, round-trip and source-map suites pass unchanged, and so do the layout goldens. The fuzz workflow passes `-timeout=2`.
27. **F17.1.** A banner, not a failure: CI never has the corpus, and failing a plain `cargo test` on a machine that has the PDFs but no extracted data would make the suite fail for reasons that are not regressions. `COLDOPEN_REQUIRE_CORPUS=1` remains the switch that fails. The banner goes straight to the stderr handle because libtest captures only the `print!` macros.
28. **F17.2.** No failing-before test is possible in the usual sense: the old fuzz copy only checked "no panic", and the bug it hid (F9) is fixed. The evidence is instead that the new check fails when the F9 fix is removed. The check calls the read-only `assess` through `dispatcher::recovery_check` (hidden from the docs), not `doc.open` on temp files, so fuzzing stays fast and never touches the disk beyond resolving a path.
29. **The reference gate on this branch** (2026-10-16): with the reference data extracted into a scratch copy of the corpus, `COLDOPEN_REQUIRE_CORPUS=1` passes with the same numbers the reviewer measured on `main`: Big Fish M1 100.0%, M2 97.4% (max Δ 2), M3 120/120, M4 99.5%; Brick & Steel and The Last Birthday Card 100%.
