# Review fixes for phases 4–5b: progress

Branch `review-fixes-4-5b`, started 2026-10-28 from `main` (75bf19c). It fixes the findings of four reviews of `7707861..75bf19c`, phases 4, 5a and 5b: Grok's (GR1–GR12), Claude's (CL1–CL8), Astra's (GP1–GP14) and Antigravity's (AR1–AR12). The reports stay out of the repository. This file is updated and pushed after every group, so where the work stands never lives only in one session's notes.

**The rule for group 1**, now in `docs/specs/changes.md` §6: accepting or rejecting a change never removes text or blocks that aren't part of that change. A mark that can't settle cleanly fails with `change_conflict` when settled by id, and otherwise stays pending and is listed in `skipped`.

Each finding gets a test made from the reviewer's reproduction. It is run before the fix, to see it fail for the reason the reviewer gives, and again after. Same-bug findings share one commit, holding the spec, the test and the fix.

## Decisions

Decided with the project's owner before any code (2026-10-28):

1. **The common rule** for settling (group 1), above.
2. **"Save anyway"** (CL6, AR3) runs every check that can refuse the save first, so a refused save changes nothing. Accepting and clearing then become one undo step.
3. **Moves of different scenes in one change** record their order, so rejecting undoes them newest first. A project holding such an order is bundle version 3.
4. **The diff past its pair bound** anchors on blocks whose text occurs once in each draft, rather than showing the unit as deleted and added.
5. **Unknown bundle entries** (GP3) are kept, not reported as a loss.

Decided while working (the project's owner asked for a list rather than questions):

6. **Old rules are frozen, not re-derived.** `crates/core/src/legacy.rs` is a verbatim copy of the settle code and the two small rules semantics 4 changed, chosen by `Exec::rules()`. The phase 5b fixture, written by 75bf19c before any fix, proves journals of semantics 3 replay as that build left them.
7. **A recovered older journal gets a `journal.semantics` marker**, as one recovered from elsewhere gets `journal.adopted` (phase 5a decision 43): one appended line, so no crash point costs work. A marker that goes down, or names semantics this version doesn't know, stops replay.
8. **Held marks keep the whole change in that block pending.** When a mark can't settle cleanly, the settle is planned again with that change's marks in that block left alone, text marks included, until nothing more is held. So a held block can still be accepted, or rejected after the other text is removed.
9. **Notes and boneyard go with an inserted block** on reject: they carry no marks (changes.md §10), so they can't be told from the change's own. Only printed text holds a block.
10. **GR1's agent gets `change_conflict`, not `not_your_change`.** Under the common rule nothing is removed, so it is a conflict for every author; `not_your_change` stays for edits that would change another author's marks.
11. **AR1 (part 1): a later split of one's own new block is a split**, as the approved plan said; a split in the same change (one batch) is still an insertion.
12. **P1, found by the new property:** a block deletion holding text no deletion marks is held too, and the accepted form keeps such a block. Same rule, same class as GR1.
13. **CL1: permission checks guard a live agent, not a record.** Replay skips the `tracked: false` refusal and the title-edit refusal; everything else replays as before.
14. **GP5: a missing file is not read at all**, for every format; its document stands as the empty one `doc.new` makes, with a new `doc_id` for a project.
15. **CL6: the "Save anyway" undo label** is "Accept changes and clear revisions" (or "Accept all changes", or "Clear revisions"). A change the accept-all skips stays pending and is listed in the warning's `details.skipped`. The background save runs the refusing checks synchronously only on the "Save anyway" path, so the Mod+S budget is unchanged.
16. **GR12: only the tracking switches** count as work a Fountain or .fdx file can't hold; nothing else in the document is both unwritten and not a loss. After a save the switch still resets, as changes.md §4 says.
17. **GR8: no change to the store.** Kept paragraphs stay keyed as they are, so projects and journals written before still work; the writer indexes them by anchor when it writes.
18. **GP2 (B): the wrapper's eight inline layout attributes are not a loss** when a dual block becomes ordinary speeches, as §14.4 already drops them when a paragraph's type changes; only its unknown attributes and children are.
19. **CL8's corpus test checks what CL8 is about.** An edited group is generated whole (G3 allows it), and two corpus files spell their dual blocks in ways the generator does not (odd indentation, a bare `<Paragraph>`), so the test asserts that nothing outside the group changes and that `StartsNewPage` keeps its value, not that only three bytes change.
20. **GP3: kept entries live in the document, not the journal header.** A header that copied them at every save could grow large; recovery reads them from the bundle on disk instead, as the change table is named rather than copied. A bundle that is gone, or is another document, gives none back.
21. **"New Act" breaks** that come from an element's settings rather than an inline attribute (found in passing) are left for later, under Deferred: no corpus file edits one, and fixing it needs the settings in the generator.
22. **GR5: moves are numbered only once a change moves a second scene.** Until then the per-heading order is enough, so most projects with a pending move stay version 1 or 2, readable by the phase 5b build.
23. **GR9 is a refusal by rules, not by live-ness.** It applies under semantics 4, as the settle rules do, so an older journal holding such an edit replays it.
24. **GR10 reads the block compared with the starting point the same way** (its distributed attributes), not only the starting point, so a block with a pending retype of its own is compared like with like.
25. **GP11 plans a settle one change at a time** and tags each operation with its change, so marking can be split by change without reordering what the settle does; `settled_rev` moves to `legacy.rs`.
26. **GR6: `scene.move` gets `last`, not a new command.** It is an optional param, so old journal entries replay as they were, and it may only take in more than the scene, never less.
27. **GR11: anchoring applies to blocks only.** Word and title-line alignment keep the rule `diff.md` §3.4 and `changes.md` §5.1 give (one deletion and one insertion past the bound), so tracked `block.set_text` and the diff still mark words the same way.
28. **CL7: "Save as PDF…" from the compare view stays on the UI thread.** The review named Compare and Review a draft; the PDF of an already laid-out comparison is the smaller cost. It is listed for later.
29. **CL7: a stale import is planned again once**, then reported; the writer can bring it in again.
30. **GR2: a mark past a limit makes `document.json` count as damaged**, rather than the mark being dropped: that is the path any failed check takes, and the readable copy keeps the text.
31. **GR7: `Document::check` also holds the .fdx store's loose children** to anchors below `next_id`, as it holds the kept paragraphs.
32. **Hostile bundles get a structured fuzz check, `bundle_hostile`.** Random bytes almost never make a zip, so the existing target could not reach GR2, CL5 or GP14. The `bundle_read` target runs both checks on the same bytes, and a proptest runs the new one on stable.
33. **The fuzz crate's lockfile was stale** since phase 5b added `coldopen-diff` to core; it is brought up to date. The libFuzzer runtime does not build on Windows, so the fuzz workflow on Linux is where the target is built.
34. **AR6: only `scene.list` and the reports read the current text's scenes.** Structural commands keep `Document::scenes`, so no journal replays differently. The counts in `doc.open`'s result and similar summaries are left as they were.
35. **AR6 in the navigator: a struck scene keeps its row**, named by its struck text, with no number, page or length, and the scenes after it are numbered without it, as `scene.list` numbers them.
36. **AR9: the reports' fallback is `CONT'D`.** With no continued string, or one that is only brackets, the built-in `CONT'D` and `CONTD` are still the marker; an empty string would have matched every extension.
37. **AR10: "This scene" under a section is the scene before it**, as Antigravity proposed, rather than nothing. The navigator's highlight stays on the section's row, so Up and Down keep working from it.
38. **AR11: a batch is followed item by item** with `result["results"][k]`; a nested batch recurses.
39. **P5 changes semantics 4 only.** Semantics 4 is new on this branch and no build has written it, so its rules can still change; journals of 1 to 3 replay through `legacy.rs` as before.
